## Verdict: `READY` — with two blocking preconditions

No reuse collisions and no contract-surface breaks. Every artifact the ADR proposes is confirmed absent, and the retirement surface is smaller on the backend than the ADR implies. The two preconditions below are **not optional** — one of them the ADR itself promotes to a Wave-1 acceptance criterion.

## Open questions — both block a clean Wave 1

1. **`taxonomyOwner` value granularity is unresolved, and Wave 1 is when it stops being free.** The ADR (as amended in `789264dc`) makes this a Wave-1 acceptance criterion: verify against the Allegro API whether `.pl/.cz/.sk/.hu` publish one tree or several **before the first row is written**. Neither shape is free if guessed wrong — `'allegro'` needs splitting if the trees diverge, `'allegro:pl'` needs collapsing if they don't, and both migrate every `DestinationCategory` row plus every category mapping that references one. This is a *fact to establish*, not a design choice. **Do this first; it is cheap and it gates the schema.**

2. **The job's subject shape depends on #1943.** Wave 1 may proceed with the connection-scoped scaffold (`connectionId` = source connection, `taxonomyOwner` in the payload) **only** for a seller-connection source. The catalogue-credentials source has no connection at all and cannot be built until `SyncJob.connectionId` is nullable. Sequence #1943 before the catalogue-source wave, and treat the scaffold as carrying a live false-provenance cost in the dead-job cockpit (`findRecentByConnectionId`, `(connectionId, jobType)` aggregation, `requeueDeadJobs`) for as long as it stands.

Unresolved but **not** blocking Wave 1: the `search` matching strategy (trigram / full-text / name+derived-path / source-name). The ADR settles that the data is local and queryable; picking the strategy can follow the schema.

## Suggested Wave-1 ordering

1. Establish the Allegro-region fact → fix the `TaxonomyOwner` value set.
2. Entity + ORM + hand-authored migration (`1833000000000`, two partial unique indexes).
3. Repository port + repository + `IDestinationTaxonomyService` (`browse` / `search`), tokens into `listings.tokens.ts`.
4. `destination.taxonomy.sync` job type + worker handler (paged, resumable, `syncedAt` watermark sweep).
5. HTTP route + repoint `mapping-options.controller` (responses byte-identical).
6. Defer: FE reader migration, `CategoriesCacheService` deletion, catalogue-only source (blocked on #1943).
