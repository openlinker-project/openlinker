## Rules
1. **Real components only** for anything the app has: import from `@web/shared/ui/*` (PageLayout, DetailSection, DataTable (needs rows/columns; MemoryRouter is provided), KeyValueList, StatusBadge, Chip, MetricCard, KpiCard, Button (tone primary/secondary/ghost/danger), Input, Select, Textarea, Combobox, SegmentedControl, FilterCheck, FormField, Dialog/DialogContent/DialogTitle/DialogDescription/DialogFooter, ConfirmDialog, Infotip, Alert (tone info/success/warning/error/conflict, density compact), EmptyState, Tabs, SetupStepper, WizardLayout, WizardSummaryRow, DocumentHeadline, DocumentLifecycle, DocumentKindGlyph, ProductThumbnail, Sparkline, TimeDisplay, CopyableId, ActiveFilterChips, QuickFilters, BulkActionBar) and from real feature components where they are pure (see your task). Read each component's file for its props before using it. `useToast()` works (ToastProvider is mounted). Providers mounted: LocaleProvider(pl), QueryClientProvider, ApiClientProvider (offline: every call rejects), MemoryRouter, TooltipProvider, ToastProvider.
2. **Styles:** use the app's classes (from `apps/web/src/index.css`) and tokens. If you need your own CSS, create `src/views/<your-prefix>.css` and import it from your view file; class names must be prefixed with your prefix. Only CSS variables from index.css (`--bg-*`, `--text-*`, `--border-*`, `--accent-*`, `--status-*`, `--tag-*`, `--space-*`, `--radius-*`, `--font-*`). Status colours only for status; gift/bundle roles use the marks. No gradients, glows, or card soup; prefer tables and structured lists. Numbers get `.tabular`.
3. **Language:** every operator-facing string in Polish, natural, plain, sentence case, imperative buttons ("Dodaj gratis", "Zapisz zestaw"), the same action name in its toast ("Dodano gratis"). Glossary: Zamówienie, Pozycja zamówienia, Zestaw, Składnik, Gratis, Promocja, Kanał sprzedaży, Połączenie, Stanowisko pakowania, Pakowacz, Rezerwacja, Stan magazynowy, Przyjęcie na stan, Zwrot, Zwrot pieniędzy, Dokument sprzedaży, Paragon, Faktura, Faktura korygująca, Stawka VAT, brutto/netto, Wstrzymanie, Wymaga uwagi, Szkic. Brand names untranslated. NEVER use an em dash or en dash anywhere (plain hyphen only). No exclamation marks, no apologies.
4. **States:** every state in your list becomes a `StateDef` with a stable id (kebab-case), a short Polish label, a Polish `note` (1-4 sentences: what the operator sees, why, what OpenLinker does underneath, e.g. where stock goes), the use-case ids it demonstrates, a priority, and channels where relevant. Add `...commonStates(...)` at the end for data screens. `render(state)` switches on the state id and renders the screen in that state. Prefer one screen component with props over copy-pasted variants. Interactions must work inside a state (dialogs open, toggles change previews, toasts show, buttons navigate with `go()` to related screens/states).
5. **Globals:** honour `useProto()`: `oms` changes stock paths (OMS on: "Zarezerwowano -> Spakowano -> Zdjęto ze stanu w PrestaShop"; OMS off: "Wysłano do PrestaShop jako pozycja 0,00 zł -> Sklep zdjął stan"); `currency` EUR shows order amounts in EUR with the PLN cost and rate (EUR_RATE); `role` viewer disables writes with the reason; packer never sees cost (the frame blocks non-bench screens for packers; on shared components just hide cost when role is packer).
6. **Facts to respect** (from the spike; do not invent behaviour):
   - Allegro and Erli have no gift feature; a gift there exists only in OpenLinker (OL rule or operator). It still leaves the warehouse: OL adds a gift line to the OL order at ingestion (id `ol-gift:{ruleId}:{lineId}`), it is reserved, packed (scanned on the bench) and taken from the owning master's stock with reason "gratis"; with OMS off it is sent to the destination shop as a 0,00 zł line and the shop lowers stock itself. A gift added after routing/packing is too late (explain the path). Pilot fallback: packer note + manual stock correction.
   - PrestaShop: a cart-rule gift arrives as an ordinary line at FULL price with the value only in the order's cart rules; same product as gift merges into qty 2. IdoSell marks gifts (`orderSalesMode: gift`), Empik (Mirakl) has `offered_quantity`. Shoper gift apps use a 0,01-1 zł variant with no flag (inferred). WooCommerce via plugins.
   - Bundles: OL-defined over a master variant; components get line ids `{lineId}~c:{variant}`; stock/reservations/packing per component; ATP = min floor; documents keep the bundle line in the pilot (component split later, proportional to standalone prices); Allegro sends `productSet` (check only); multipack productSet qty>1 on a single-variant mapping is held; WooCommerce/Shoper may send children as lines (double count guard); editing a bundle line is refused (LINE_IS_BUNDLE); PrestaShop pack in components mode cannot be decremented (blocked).
   - Documents: gift form is an operator setting (omit same-rate / hold cross-rate / 1 grosz / priced-in share / internal art. 7 ust. 2 record). eparagony refuses a VAT rate with value <= 0 (error 41). "List price + 100% rebate" is high risk (KIS 2026) - show it as not offered or warned. Never present this as legal advice.
7. **Quality:** responsive to 400 px (no horizontal page scroll; wide tables inside `.data-table__container` scroll themselves), keyboard focus visible, no console errors. Keep each file readable; split into components.
8. **Do not** edit files you do not own, run git, or touch the repo. Do not change `src/proto.tsx`, `src/model/*`, `src/ui/*`, `src/App.tsx`, `src/main.tsx`, `src/views/index.ts`. If you need extra mock data or helpers, put them in your own files (`src/views/<prefix>-data.ts`).
