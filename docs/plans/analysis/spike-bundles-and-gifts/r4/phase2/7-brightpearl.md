## Core model in one paragraph (all quoted)

- A bundle is its own product record flagged on a "Bundle" tab: "Select the Bundle tab . Select Yes to identify this product is a bundle of others." ... "A total of 40 different items can be added into a single bundle." [H2]
- It is virtual: "Bundles are always non-stock tracked and will display with a blue background on the products list." [H2]; "the component parts are still, in principle, available for sale separately since their stock is not consumed by listing them within a bundle." [H1]
- API shape: product `composition`: "Details the composition of the product i.e. is a bundle"; `bundleComponents`: "Details the component products of the bundle." with `productId`, `productQuantity`, and "composition: the composition of the bundle component product." [A1]
- On an order the bundle explodes: "When a bundle is added to an order, the items within the bundle will explode out onto their own lines once the order is saved. The sell price is taken only from the bundle record" [H3]. API: "Note that when adding a product which is a bundle to an order, the children are automatically added as individual order lines. This relationship can be seen in the read-only properties bundleChild, bundleParent and parentRowId" [A6]. Row fields: "bundleParent ... Whether or not this row is the parent row of a bundle. The child rows will refer back to this row by its ID." / "parentRowId ... If this row is a bundle child, this property is the ID of the row's bundle parent row. Otherwise, it is null." [A5]. The Order GET example uses `"composition": {"bundleParent": true, "bundleChild": false, "parentOrderRowId": 0}` on the parent and `"parentOrderRowId": 149` on children, with the parent row `"rowNet": "12.5000"` and every child `"rowNet": "0.0000"` [A4]. Note two spellings of the same link (`parentRowId` in Sales Order GET, `parentOrderRowId` in Order GET).

## Conflicts and doubts

1. **Nested bundles.** The API shows bundles inside bundles: "bundle 391 is itself a component of bundle 488" and "a complete list of all bundles that contain a given product either directly or indirectly, in a tree structure" [A2]; each `bundleComponent` carries its own `composition` [A1]. A search-engine summary claimed the current help centre says Brightpearl "only allows a single level of bundles and does not support nested bundles" - I could not load that page (JS-only), so it is **unverified**. Trust the API doc for the data model; treat nested-bundle *support in UI/ordering* as Unknown.
2. **"Stock bundles".** Bundle Availability API: "This message is only applicable to stock bundles." [A3] vs help: "Bundles are always non-stock tracked" [H2]. Probably "stock bundle" = bundle of stock-tracked components; terminology is inconsistent.
3. **Bundle stock sync to channels changed over time.** 2016 Shopify/BigCommerce: "Inventory sync No" and "availability will need to be manually managed" [H12][H13]; 2017 core article: "we now support bundle inventory across all integrated sales channels" [H2]; 2018 BigCommerce: "Inventory sync Yes - complete bundles at a warehouse only" [H14]. Trust the newer statements.
4. **Allocation on download.** Shopify/ekm 2016: "The inventory will not be automatically allocated for a bundle" [H12]; Amazon 2018: "all the items within the bundle are added to the sales order and the inventory is allocated and reserved" [H8]. Per-connector, and probably improved since.
5. **Magento-owned bundle on the order.** 2016: "The order will display details of the bundle (which gives the sell price) plus each individual stocked item ... (these have a zero price)" [H16]; 2022: "will show only the simple products, or the components" [H17]. Trust 2022 (B-06 rated on it).
6. **Where cost sits.** Help: "all of the cost from the sale will be recorded against the bundle components" [H6]; API example shows `"itemCost": "5.0000"` on the parent and `"0.0000"` on children [A4]. The API example may predate shipping (cost of sales is posted at shipping). Unresolved.
7. **Age.** Most help quotes are 2016-2022 snapshots; Brightpearl (now Sage) may have changed since. The live help centre could not be read.

## Integration normalisation

- **One bundle owner, linked by SKU.** Brightpearl wants the bundle defined in Brightpearl and linked SKU-to-SKU to a single product/listing on the channel: "It is the bundle which is linked to the single product in ekmPowershop by using the same SKU." [H15]. Bundles are never imported from a channel [H8][H12].
- **Explosion happens at order save, inside Brightpearl,** with read-only parent/child links on rows (`bundleParent` / `bundleChild` / `parentRowId`) [A5][A6]. Price on parent, zeros on children [A4].
- **Alternative mode where the channel owns the bundle (Magento)**: only components are linked, channel prices taken as-is, and the docs explicitly forbid linking both sides to avoid double components [H16][H17].
- **Per-connector feature matrix published in docs** (inventory sync, price sync, order download, stock allocation, shipment update, split shipment, tracking) [H8][H12][H14][H15]; behaviour on shipping a partial bundle differs per channel [H8 vs H12].
- **Discounts:** per connector, not normalised: negative misc row with default discount nominal code (Shopify/BigCommerce/ekm), per-row discounted price (Magento) [H18][H17]; coupon code put in the row description (Shopify) [H19].
- **Gift-related channel data:** gift wrap as its own row; gift messages into a custom field configured on the channel settings [H19][H20].
- **Unmapped products** become free-text non-stock rows that cannot ship and must be swapped by the operator [H19][H20].

## UX patterns worth copying

1. **Published per-connector capability table for bundles** (sync stock / price / order download / allocate / shipment update / split shipment / tracking) [H8][H12][H14]. Maps directly to our adapter-declared capabilities.
2. **Read-only parent/child row links plus expanded rows on the order** (`bundleParent`, `bundleChild`, `parentRowId`) [A5]; children exist as real rows for picking and stock.
3. **WMS pack-bench settings for bundles**: show bundle as one line with expandable components, scan either the bundle barcode (pre-packed) or components, warn on mixing, force "pack bundle items together" [H4][H31].
4. **Bundle availability per warehouse counting only complete sets**, plus a reverse lookup "which bundles contain product X" [H5][A2][A3].
5. **Rule engine for free items** with ANY/ALL/NONE row conditions, explicit rule order, once-per-order guarantee, order note on every run, and a recommended "error status" [H22][H24][H25][H26][H27].
6. **Separate print settings** for invoice vs goods-out note (bundle line only / bundle + components) [H3].

## Anti-patterns

1. **All price and tax on the parent, zero on children** [A4][H3]: no mixed-VAT split (B-14), no component refund price (B-15), and the margin report shows "100% profit" on the parent and "100% loss" on components, fixed only in a spreadsheet [H6].
2. **Gift stock-out waits silently**: free SKU must be on hand, the order goes back to the watch list, and stock problems explicitly do not raise the error status [H22][H23][H27] (violates G-08 / G-16 "never silent").
3. **Discounts encoded differently per connector** (negative row vs per-row price) and analytics only reads the row Discount field [H18][H33], so channel discounts are invisible in discount reporting.
4. **Inconsistent "shipped" rule for split bundles**: Amazon marks the bundle shipped at the first component; Shopify/BigCommerce wait for the full order and send no tracking for bundles [H8][H12][H14].
5. **Variant choice = one bundle per combination** [H2], and **bundle contents fixed on the order** [H3]; plus an irreversible discount-column setting [H32].

## New use cases (with source)

- **N-01 Nested bundles + reverse lookup**: a bundle whose component is another bundle; "which bundles contain this SKU" (to recompute availability or stop selling). [A2]
- **N-02 Bundle on purchase orders**: buy a bundle from a supplier, receive the components into stock at the PO cost. "it is the components of the bundle which will be received into stock at the cost price used on the order." [H10]
- **N-03 Demand planning from bundle sales**: component replenishment includes demand coming through bundles. "Demand Planner will ensure you purchase enough inventory to meet demand for sales of an individual item and sales of any bundles of which it is a component." [H11]
- **N-04 Linking-mode guard**: refuse or warn when both channel-side and OMS-side bundle definitions are linked for one product (double components). [H16]
- **N-05 Pre-packed bundle scan**: scan one bundle barcode instead of each component when kits are pre-packed in bags/cartons, while stock stays on components. [H4]
- **N-06 Sample stock in a separate warehouse and gift-cost reclassification** to a marketing expense account. [H21]
- **N-07 Per-item gift message** stored with the item it belongs to (SKU prefix). [H20]
