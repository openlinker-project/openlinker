# Phase 2 / 7 - Cin7 Core (DEAR) with Cin7 Omni for contrast: bundles/kits, free items, integration normalisation

Researcher: product researcher, 2026-11-04. Read-only. Primary sources: Cin7 Core help centre (help.core.cin7.com, read via the public Zendesk JSON API `/api/v2/help_center/articles/{id}.json`), Cin7 Core community feature requests (Zendesk `/api/v2/community/posts.json`, ~1 089 posts scanned by title), Cin7 Omni help centre (help.omni.cin7.com, same API), Cin7 Core API reference pages hosted on the help centre (Sale POST, SaleCreditNote). Reviews: one Shopify App Store review cluster, one third-party review (weak signal).

## 0. Mental model (read this first)

**Cin7 Core has no "bundle" object. A kit is an ordinary product with an Assembly BOM.** Everything bundle-like is an inventory transformation:
- **Manual assembly** = pre-built kit with its own stock. Assembly order converts components into finished units.
- **Auto-assembly** (checkbox on the BOM tab) = virtual kit. Only components are stocked; authorising a sale of the kit auto-creates and authorises an assembly order at the sale location. Availability of the kit = what components can build + any assembled units.
- **Picking for kitting** (WMS) = hybrid. Use assembled units first; if short, picker is told to pick components and the system auto-creates the assembly order. No partial pick.
- **Auto-disassembly** = the reverse on purchase (buy a case, stock singles) and on credit-note restock (a returned kit is restocked as its components).
- The **sale line stays the parent SKU**. Components never become sale lines in Core; they appear only on the assembly order, the "Expanded pick list" and the WMS pick "expand" button.

**Cin7 Omni** is the contrast: a product with "Order Type = Kit" and a BOM gets **Virtual Stock** (min over components, same branch), and each channel integration has **"Automatically Load BOMs for Kits" (Yes/No)** which, when Yes, *expands the kit line into component lines on the sales order*. That is the closest thing in the Cin7 family to a per-channel "explode the bundle" switch.

**Free items** are modelled as **a normal sale line with Discount = 100%** ("For free items discount is 100" - Sale POST API). Rules ("Product Deals") can make an item free when Buy-X criteria are met, but they apply only to Core-native, B2B portal and POS sales, not to orders downloaded from e-commerce channels, and do not auto-insert the free line (two community requests, 2024 and 2026).

**Gift wrap** = an "additional charge" (non-inventory service line) with its own channel tax rule mapping. Gift *message* is mapped into notes (Magento 2). Gift *cards* are a liability-account mapping, not a gift item.

## 2. Integration normalisation

How Cin7 maps heterogeneous channels onto one sale model (Core: Lines[Price, Discount%, Tax] + AdditionalCharges[service lines]):

1. **Discount placement is a per-channel setting, but only for Shopify.** Shopify Setup: "Add a discount as" = Price reduction (order discount distributed proportionally into line prices; item discount stays on the line) or Additional charge (one negative service line per discounted order line, Comment = SKU, Description = "Discount" or "Discount {code}" if "Bring discount codes from Shopify" is on; each carries that line's tax rule "so discount tax is correctly calculated ... and in the event of a refund"). All other channels: order discount is one order-level negative additional charge, deliberately "without distribution by lines". BigCommerce/Magento: optional coupon name on the charge. Core "does not perform any discount calculations" on downloaded orders.
2. **Kits: two philosophies.** Core keeps the channel's parent SKU on the sale and normalises at the stock layer (auto-assembly order consumes components), configured per channel by "Process auto-assembly as" (ordered qty vs minimum required). Omni normalises at the order layer: per-channel "Automatically Load BOMs for Kits" Yes/No explodes the kit line into component lines (only for Order Type = Kit; ignored for Amazon FBA orders). Omni B2B store: "Expand BOMs on order download".
3. **Non-goods money = "additional charges" with per-channel tax mapping.** Shipping, gift wrapping, handling, duties, tips all become additional charge lines; each channel exposes its own tax rules for these and the integration Setup maps them to Cin7 tax rules ("Default Additional Charges Tax Lines").
4. **Channel-SKU-to-product aliasing via a 1-component BOM.** "Import duplicate SKUs from Shopify": each Shopify variant with a duplicated SKU becomes a "KitProduct" (SKU = Shopify VariantID, Not for Sale) whose Assembly BOM holds one component, the MainProduct; auto-assembly + auto-disassembly on. Sale and fulfilment show only MainProduct; stock pushes fan out to all variants. The BOM engine is reused as a mapping table.
5. **Order capture/idempotency knobs per channel**: capture on Created/Paid/Fulfilled, exclusion tags, delay downloads (recommended for post-purchase upsells), consolidation, invoice draft vs authorised, processing mode (auto pick/pack/ship), log-based dedup (an order in the Log is never re-imported; edits after download are NOT captured - reload = void + delete log + reload).
6. **Gift cards are mapped to a liability account**; an order containing a gift card stays in Pending until the account is mapped (hard stop rather than silent wrong posting).

## 3. UX patterns worth copying
- One BOM object, behaviour switched by a mode (manual / auto-assembly / pick-for-kitting / auto-disassembly) instead of separate "kit" and "bundle" entities. Maps well onto "pre-built vs virtual" (B-03) as a per-product mode.
- Hybrid fulfilment "use assembled stock first, then build from components" (picking for kitting) - good default for B-03.
- Per-channel, named settings in the integration's Setup tab ("Add a discount as", "Process auto-assembly as", "Automatically Load BOMs for Kits") - a direct precedent for X-03.
- Hard stop with a named reason instead of silent posting (gift card order held in Pending until liability account mapped; auto-assembly backorder prompt + "Out-of-Stock Components for Auto-Assembly Report").
- Expanded pick list / WMS expand-collapse for kits: parent stays the sale line, components appear where the picker needs them.
- Rule builder phrasing: "Buy [qty / brand / category / tag / order total] -> Get [qty / product]" with Effective From/To, customer scope and coupon gate.

## 4. Anti-patterns (and what Cin7 users complain about)
- Free gifts by rule are not auto-inserted; a deal only discounts a line a human already added, and deals do not run on e-commerce orders at all (community requests 2024 and 2026).
- Two incompatible discount encodings depending on channel (distributed line reduction vs one undistributed order charge) - breaks per-line refunds and per-component VAT.
- Kit availability only computed when auto-assembly is on; manual kits read as out of stock online. Availability coupled to a fulfilment mode instead of being a separate setting.
- Same-location constraint for virtual kits (Core auto-assembly; Omni virtual stock per branch) - components in two warehouses make the kit unsellable.
- Order edits after download are not captured; fixing = void + delete log + reload. Batch-numbered auto-assembled kits cannot be edited without voiding assemblies.

## 5. New use cases surfaced
- NEW: Channel listing alias -> product via a 1-component kit (duplicate SKUs across several channel listings mapping to one stock item, fan-out stock push).
- NEW: Auto-assembly quantity policy (build exactly the ordered qty vs top up to cover negative availability / min stock).
- NEW: Do not expand kits on orders fulfilled by the channel (Amazon FBA) - expansion must depend on who fulfils.
- NEW: Delay order capture so post-purchase upsells / gifts added after checkout are included.
- NEW: Non-invoiced pack-stage items (packaging, inserts, flyers) - not a gift line, but must be picked/packed and weighed (community request).
- NEW: Fractional BOM (sell singles from a bulk pack) and readable pick quantities.
- NEW: Component substitution at order time when a BOM component is out of stock (community request, overlaps B-12).

## 6. Confidence
- High: Core BOM/auto-assembly/picking-for-kitting/credit-note auto-disassembly; Core discount mapping per channel; Product Deals scope and the "not auto-added" gap; Omni "Automatically Load BOMs for Kits" and virtual stock.
- Low / unverified: how Magento 2 bundle orders are actually mapped; whether Omni loaded component lines carry prices; how restock of a single component of a sold kit works in practice; packing-slip content for kits.
- Thin signal: reviews (one Shopify App Store listing 2.9 stars from 49 reviews with an auto-assembly/WMS complaint; one third-party review) - not used for conclusions.
