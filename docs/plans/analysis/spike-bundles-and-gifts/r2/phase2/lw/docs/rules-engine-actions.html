Rules Engine: Actions

There are several Rules Engine actions that can be performed on an order. Actions represent the “THEN” part of the “IF this, THEN that” logic used in order fulfillment — what happens to the order when specific conditions are met. For example: IF the destination country is Italy, THEN move the order to the "Italy Orders" folder. In this case, “Move order to folder” is the action. 

This guide offers a comprehensive overview of all actions currently supported in the Rules Engine. 

Available Rules Engine actions

Below is an overview of all actions currently supported in the Rules Engine. 

Add items to an order NEW

This action allows you to automatically add specific SKUs to an order when certain rule conditions are met. 

Many businesses include free gifts, samples or promotional items based on order value, product type, or customer segment. This action helps automate that process so the correct item is added without manual intervention.

  • 💡Example use case: As a business that includes free gifts with orders over £100, I want those gifts automatically added to the order once the qualifying condition (e.g., “Order Total > £100”) is met. 

This action is especially powerful when combined with other actions like assigning order tags or identifiers for prioritization, and folder assignment, enabling full automation of promotional workflows.

How the Add Items to an Order action works

When configuring this action, you will need to define the following: 

  • Action name: A descriptive name for internal reference (e.g., “Add a free gift”). This is a *required field. You must enter a name to save the action.
  • Action type: Set to Add items to an order. 
  • Action value (SKU search): Begin typing the SKU in the search field. Linnworks will return a list of up to 20 matching SKUs. Select the appropriate SKU to add it to the order.
    • You can add up to 10 SKUs in total per action. 
    • Each added SKU will appear in a separate row with quantity and pricing details.
  • Quantity: Specify how many units of the item should be added. 
  • Retail price including tax: This field automatically retrieves the retail price including tax from the product details in My Inventory.
    • The tax rate is determined by the product details. There, you can either assign a fixed tax rate or configure the item to use the order's destination country tax rate.
    • The currency displayed is based on your account’s General Settings > Currency.
  • Discount: Optionally apply a percentage discount to the item. For example, enter 100% for a completely free gift.
  Note: When using the Add Items to an Order action, it is important in some cases to check whether the order was merged, split, or is a resend. These cases are explained in detail in the Auto-Adding Items & Services: Extra Conditions guide. Please review it before you start using this action. 

Once the rule with this action is saved, the system will automatically add the defined item(s) to every order that meets your rule’s condition (e.g., “Order Total > £100”)

  Important: You cannot manually change the tax rate or define it in the Rules Engine action. Ensure your inventory settings are correctly configured if tax handling is important for this rule. 

Add notes to an order NEW

This action allows you to automatically add custom notes to orders that meet the rule conditions. Notes can be used for internal communication, to provide instructions for processing, or to pass information externally to customers or sales channels. 

How the Add Notes to an Order action works 

When configuring this action, you can define: 

  • Note text: The content of the note to be added.
  • External: Enable this option if the note should be sent to external systems or channels that support notes (e.g., buyer-facing). You can also add the note as an external one if you need it to be visible on the invoice when it is printed for the order. 
  • Processing: Enable this option if the note is relevant for order processing within Linnworks (not buyer-facing). 

You can add multiple notes within the same action by selecting Add note and defining the text and settings (External and/or Processing) for each note. 

Once the rule is triggered, the defined note(s) will be added to the order and displayed in the Order Notes section.

💡Example use case:
  • A rule is set to trigger when the order value is above £500.
  • The Add notes to an order action is configured with the text: "High-value order – verify payment before dispatch" and the Processing option enabled.
  • When such an order is downloaded, the note is automatically added and visible to the processing team.

Add services to an order NEW

This action allows you to automatically add service-based line items to orders — ideal for businesses offering additional services such as gift wrapping, assembly, custom packaging, or similar. 

If you offer optional or bundled services for specific types of orders (e.g., high-value orders, orders to specific regions, or customer-requested add-ons), this action helps automate that process.

  • 💡Example use case: As a business that offers services like gift wrapping for specific orders, I would like to automate adding those services to orders. 

How the Add Services to an Order action works

When configuring this action, you will need to fill in the following fields in the action setup screen: 

  • Action name: A descriptive name for internal reference (e.g., “Add Gift Wrapping Service”). This is a *required field. You must enter a name to save the action. 
  • Action type: Set this to Add service to an order. 
  • Action value: Click Add service to create a new service entry. Each click generates a new row. You can add up to 10 services per rule action. In each row, configure the following: 
    • Quantity: Defaults to 1, but can be changed as needed. 
    • Service name: This is a *required field and must be entered manually. A placeholder will be visible until it is filled in. 
    • Retail price including tax: This is the full price including tax. It must be entered manually. 
    • Discount: Optionally enter a discount for the service item. Default is 0%. 
    • Tax rate: Manually set the applicable tax rate for the service. With the Add service to an order action, service lines are not linked to a physical inventory item, so the tax rate must be manually defined within the action itself. Currently, there is no option to automatically apply a country-specific tax rate for service items. 
  Note: When using the Add Services to an Order action, it is important in some cases to check whether the order was merged, split, or is a resend. These cases are explained in detail in the Auto-Adding Items & Services: Extra Conditions guide. Please review it before you start using this action. 

Once the above is configured and saved, the defined service item(s) will be added to any order that meets your rule’s conditions. 

Assign a tag to order

This action applies a visual tag to an order, making it easier to quickly identify or prioritize the order based on your own rules. 

  • Tags are predefined icons in Linnworks. There are two shapes (star and circle) in three colors (red, green, blue), giving you six distinct tags to choose from.
  • You cannot create custom tags, but you can use those already available in Linnworks to represent internal rules or workflows.
    • Example: A red star could indicate “Urgent – Process Immediately”. 

Tags are particularly useful on the Open Orders screen, where they act as quick visual markers for staff to spot and filter specific orders. 

Assign an identifier to order

This action applies an identifier to an order, which can include both a text label and an image. Identifiers help categorize and flag orders for specific handling, reporting, or automation purposes. 

  • Linnworks includes a set of predefined identifiers (e.g., "Amazon Premium Order," "Collection Order," and "In Pickwave"). These are applied to orders automatically when they are downloaded from the sales channel or when specific actions occur — such as adding an order to a pickwave. 
  • You can also create custom identifiers, each with a name and optional icon to visually distinguish them. Custom identifiers can be created in Settings > General Settings > Order Management > Identifiers.
    •  Only custom identifiers can be applied to orders via the Rules Engine.

Assign order extended property

This action allows you to add a custom extended property to the order, which can be used to store additional information not captured in the standard order fields (such as customer details, items, or shipping information). 

Order extended properties are highly flexible and can store any custom data relevant to the order, such as delivery instructions, internal notes, third-party references, or workflow flags. 

How the Assign Order Extended Property action works

When configuring this action, you will need to define:  

  • Type: This is the extended property type. New accounts have only one default type available — Attribute. Once you start downloading orders from your sales channels, any extended property types included in those orders will also appear in the drop-down list here. You cannot create custom types manually, so when assigning a custom extended property, you must choose either the default Attribute type or one that was saved from your channel orders. 
  • Name: This is the name of the extended property. Unlike the type, you can create custom extended property names. For example, you can have multiple properties with the Attribute type but different names like Color, Material, or Size. How the Name field works: The Name field is a free-text field (with backend validation):
    • You can manually enter the name of the extended property.
    • If the extended property name does not exist in your account, an error message will be displayed ("There was a problem with adding the action: The extended property does not exist"), and the rule cannot be saved. To fix the error message, manually assign the extended property with the new name to at least one order first. Once that is done, the name can be safely typed in here. This step only needs to be done once — after that, the property can be added automatically via automation rules.
      •  Note: Previously, this field was a drop-down. It was updated to improve performance for accounts with a large number of extended properties, where loading the full list could cause timeouts. 
  • Value: This is the value assigned to the extended property you’re adding to orders. For example:
    • Type: Attribute
    • Name: Color
    • Value: Red

To learn how to manually add extended properties to your orders, see this guide. 

Assign order to folder

This action assigns an order to a folder. Note! An order can be assigned to multiple folders. However, if an order can only be associated with a single folder is enabled, and the Rules Engine is running on an order that is already assigned to a folder, this order will be re-assigned and removed from the former folder.

Assign order to location

This action assigns an order to a location.

Assign postal service to order

This action allows a Linnworks postal service to automatically apply to an order. For more information on postal services, see this guide. 

Block orders from merging

This action adds to orders a Block from merge identifier that blocks orders from being automatically merged when the Auto Merge Orders setting is enabled in Settings > General Settings > Order Management. These orders will just be ignored. More details are here. 

Execute a macro

This action executes any custom macro previously set up in the Macro Configuration screen.

Lock order

This action locks orders. Locked orders cannot be edited without being unlocked. While an order is locked, the items from the order don't affect the Available Stock Level calculations. 

Park order

This action parks orders. Note that parked orders cannot be edited without being unparked. While an order is parked, the items in the order continue to affect the Available Stock Level calculations.

Send to fulfillment network

This action allows you to send orders to the fulfillment network(s), which are explained fully in this guide.

Set dispatch date - relative to received date NEW

The Set Dispatch Date action allows you to automatically set a dispatch date and time for an order, based on the date the order was received in Linnworks. It is one of the latest enhancements to the Rules Engine, designed to help you unlock greater efficiency by automating more stages of the order lifecycle. This action ensures your dispatch schedules align with your delivery offerings and SLA commitments, especially when tied to customer shipping choices. 

The Set Dispatch Date action is one of the few new Rules Engine actions being released gradually, aimed at helping you to save time, prevent errors, drive more sales and delight your buyers.

How the Set Dispatch Date action works

When configuring this action, you will need to define: 

  • Dispatch date offset: Specify how many days after the order’s received date the dispatch should occur. 
    • For same-day dispatch, enter 0 days.
    • For next-day dispatch, enter 1 day, and so on.
  • Dispatch time: Set the exact time of day (e.g. 03:00 AM or 04:00 PM) when the order should be dispatched.
 Note: If you are configuring same-day dispatch (with a dispatch date offset of 0 days), you still need to specify a dispatch time. If the time you set is earlier than the time the order was received, Linnworks will not backdate the dispatch. Instead, the system will set the dispatch date to match the received date, ensuring  your dispatch times are always logical and achievable. 

Split order into packages of maximum value

Order will be split into packages with a maximum value set in the action. The value will be based on the unit price of the ordered item. Composite children will use an equal share of the value of the parent. 

Split order into packages of maximum weight

Order will be split into packages with the maximum weight set in the action. With composites, only the children will be used. Note! This action will split the order into several packages, with each package containing items weighing no more than the limit set by the action in the ruleset. During the split, neither the type of packaging nor the weight of the packaging will be considered; only item(s) weight is taken into account. 

Split order into packages of single items

Order will be split into packages with only one item in each.
