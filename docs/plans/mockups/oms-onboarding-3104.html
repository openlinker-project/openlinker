Settings

Set up the pack bench

OpenLinker can do your picking and packing itself, on a screen built for someone standing at a bench with a scanner. None of it is on by default. Adding the connection changes nothing on its own — until step 4, your shop keeps deciding where orders ship from, exactly as it does now. About 20 minutes, if nothing is in your way.

Right now

What OpenLinker can see

0 of 6 done

These are reads, not ticks. Steps 1–5 are each derived from something OpenLinker can check — the connection list, its enabled roles, the active-location count, the who-decides status, and (for an administrator) the user list. Step 6 is the only one nobody can check for you, because it is the packer opening their own screen. Nothing here is stored, so closing this page loses no progress.

Six steps

What to do, in order

Steps 1–5 are an administrator’s. Step 6 is the packer’s.
    How to get back to this page

    Proposed. A route under Settings — breadcrumb Settings / Set up the pack bench — reached the same two ways the “Who decides what” page is. It is deliberately not administrator-only: a packer or an operator whose bench is empty needs to be able to find out why and hand their supervisor a step number, rather than a description of a blank screen. Every write inside it is administrator-only individually.

    1. Settings in the sidebar, then the Set up the pack bench tile, beside “Who decides what”.
    2. From the connection, once one exists: Connections → your OpenLinker OMS → Health.

    Two doors an earlier draft of this mockup proposed, and why they are not here

    A link from the bench. Every read this page makes is restricted to administrators, operators and viewers — a packer following such a link would land on a page where nothing loads. The bench keeps its shipped advice instead: “Show this screen to your supervisor.” It is also the one screen that must not link out at all: it tolerates a signed-out session on purpose, and its idle lock signs the packer out, so a link into the rest of the app would bounce a half-packed parcel to the login screen.
    The command palette. It indexes sidebar entries only, so it cannot reach a page that has none. /settings/who-decides is missing from it for the same reason.

    Scope

    What this page deliberately does not do

    • It does not buy shipping labels. The bench picks, packs and verifies a parcel; whether OpenLinker also buys the label is a separate setting, and by default the marketplace ships. Turning this on gives you a packing screen, not a dispatch desk — that is the second half of the workflow and it is not covered here.
    • It does not author sourcing rules. With none, every active location stays a candidate and the most permissive split applies, which is the right default for one warehouse. Rule authoring is its own surface (epic #3055); its six admin routes have no frontend caller today.
    • It does not manage locations beyond minting the first one. The first location is created with its country and postcode blank, and those are exactly the columns the nearest and ships-to-country rules read — so a multi-warehouse operator needs the locations surface (epic #3063). Four of its six routes have no frontend caller today.
    • It does not redesign the bench. The bench is built and real. Reference screenshots: docs/plans/mockups/oms-wave3b/screenshots/.

    Add the OpenLinker OMS

    This is the whole form. There is nothing to type in beyond a name.

    OL
    OpenLinker OMS
    No API key, no password, no URL. OpenLinker is already talking to itself.
    Adding this changes nothing on its own

    Your shop keeps deciding where orders ship from until step 4. Nothing is routed, nothing is held, no order changes path.

    Change who decides what?

    This only affects what happens from now on. Anything already in progress — a parcel someone is packing, a label already bought — keeps its current arrangement until it finishes.

    What changes

    Where does an order ship from?
    Wherever the order lands today becomes OpenLinker
    OpenLinker will decide this from now on.
    Where does the order get created?
    Your shop, as it does now becomes OpenLinker only
    Orders OpenLinker routes are no longer copied into your shop at all.
    Read the second row before you save

    It is the one that surprises people. Anything you do in your shop today with these orders — invoices, picking lists, stock counts, the customer’s “my orders” page, a second person packing — stops seeing them. Orders your shop raised itself are untouched.

    “Who picks and ships?” is not changed here

    That one is granted per parcel, when OpenLinker offers work and your bench accepts it — it follows from the role you checked in step 1, not from a setting on this page. Its row on Who decides what will keep reading “Whoever the order lands with” even once OpenLinker is doing the picking. Proposed: saving here should also write that row’s own setting, purely so the page stops saying something untrue — nothing reads it, so it changes no behaviour.

    This cannot be saved yet

    OpenLinker refused the change and wrote nothing.

    No place to ship from

    Fulfilment routing cannot be enabled until at least one active inventory location exists. Create one first — the connection’s routing readiness panel offers a default.

    That is the API’s own refusal, near enough word for word. Routing against no locations would make every order unfulfillable, so the feature would read as broken when it is merely unconfigured — the refusal names the remedy instead.
