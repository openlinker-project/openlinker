Round 2 — the two-panel layout didn't work, and here's why new

First cut split the screen into a roster sidebar and a separate unassigned pool — reviewed as disjointed, and a fresh layout-specific research pass explains why: the Gestalt law of proximity says items placed apart read as unrelated even when they're logically connected. A tech-lead pass recommended fixing it with Kanban columns (one per packer); the layout research pass found something more specific and better triangulated — five independent products (Microsoft Project Team Planner, Ganttic, Syncfusion Gantt, Onfleet, Route4Me) all converge on the SAME shape, and it isn't columns. Each keeps the roster and the unassigned pool on one continuous axis, with "Unassigned" as a peer row among the named workers' rows, not a separate panel or a set of side-by-side columns.

That's what's below: one lane per packer, "Unassigned" pinned at the top (Onfleet's and Ganttic's placement — the thing needing action first). This is also where the real app's own navigation sidebar lives — the first draft borrowed a kiosk screen's chrome by mistake, and this is an ordinary admin page.

Round 3: the cards were still the wrong shape — a fixed-width tile per parcel breaks down the moment a lane holds more than a handful, and the "Unassigned" header's full amber fill read as muddy rather than as a real accent. Rows now, dense like the app's own tables, scaling to however many parcels a shift actually has; the header is a thin top rule instead of a filled band. And drag-and-drop now sits ALONGSIDE the "Move to…" menu rather than replacing it — dragging is faster once you know the board, but it's mouse-only and invisible on first look, so the menu stays the real, keyboard-reachable path (the accessible-drag-and-drop convention: model the action, expose a plain click alternative, never make dragging the only way in).
