Sourcing · OpenLinker OMS

Sourcing rules

These rules decide which of your locations ships each order, and whether an order is allowed to go out as more than one parcel. They run top to bottom: each one either rules out locations that can't do the job, or ranks whichever locations are left.

For example — rule out any location with no stock, then rank what's left by postcode closeness to the buyer. Every order then ships from whichever qualifying location scores closest, automatically, with no one picking it by hand.

These rules never pick a carrier. Which courier collects the parcel is configured per connection under Fulfillment on its Mappings tab — a different screen, with a different job.

Splitting limit Each rule can set its own cap on splitting. When more than one rule is active, OpenLinker always uses the strictest cap — so a single strict rule can quietly cancel out several others that would have allowed more splitting. This box always shows the cap in effect right now, and which rule is responsible for it.
⇕

No split ●○○
The whole order ships from a single location — or not at all.
Line split ●●○
Different items can ship from different locations. Each item still ships whole, from one place.
Quantity split ●●●
Even a single item's quantity can be split — e.g. 2 units from one location, 3 from another.

ⓘ If none of your locations can fulfil an order, those items aren't shipped — they're flagged for a refund or return instead.

What this doesn't do yet
  • Stock isn't reserved. "In stock" checks whether any units exist right now, not whether they're already promised to another order — two orders racing for the last unit can both pass this check.
  • No shipping cost or carrier rate. Rules rank by postcode closeness, item coverage, or the order you set — never by which location is cheaper to ship from.
  • Every save is live immediately. There's no draft or second-person approval step before a rule change starts deciding real orders.
  • The rule list is fixed. You can't rank or filter by a custom location attribute (capacity, operating hours, 3PL contract terms) — only by what's built in above.
  • Bringing a retired rule back is an edit, not a button. You revive one by opening it and clearing its end date. If a rule of the same type and name is already running, the save is refused rather than silently taking over — retire that one first.
  • "Test against an order" isn't wired to anything. The dry-run read it needs (FulfillmentRouterPort.evaluate()) is declared in core with no caller — tracked as #2954. The panel is designed here; it doesn't work yet.
