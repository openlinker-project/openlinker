#1996 · Shared Order & Connection cells

One Order cell and one Connection cell, across six lists

Orders, Products, Listings, Customers, Shipments and Invoices each answer „which order is this?” and „where did it come from?” in their own way. This is the specification for answering both the same way everywhere.

Scope. Two shared compositions plus one label helper — no new shared/ui component. The full Listings-page redesign stays with #1965 and its own accepted mockup; frame 06 here touches only that page’s Platform and Connection columns, so the redesign inherits the shared cells. Cells marked † need data that does not exist in today’s API and arrives with #1995.

The problem. hide-below-1024 fires at max-width: 1023.98px, so it is already active at 768 — that value means „desktop only” in practice. It drops the Connection column on Products, Shipments and Invoices: three of the five lists that gain the shared cell, and precisely the three where today’s rendering is worst (Products shows a name with no id at all, Shipments the same, Invoices hides the id in a title attribute — invisible, unselectable, unreachable on touch). Pre-existing behaviour, but #1996 inherits it together with a promise it then fails to keep.

The decision: relocate, don’t hide. Orders already proves the pattern — its Channel column disappears at 768 too, but the pill folds under the order name (.orders-order-channel, index.css:8902-8907), so the fact moves rather than vanishing. Simply lowering the three thresholds to 768 was the cheaper option and was rejected: it keeps the column at the cost of pushing it behind horizontal scroll, and a fact you must scroll to find is one an operator stops checking.

Each host cell is chosen by meaning, not by free space — see the table below. Products folds into Product (where the product came from is that column’s subject), Shipments into Processor („Carrier” and „which carrier connection” are one question), Invoices into Document type (what the document is and who issued it are the same sentence). Listings and Customers need no fold: their column is hideBelow: 768 and survives.

The fold carries the name, not the id — a deliberate reduction. The id exists to be copied, and the Copy button reveals on row hover, which does not exist on touch. At tablet width the question is „which connection is this?”, which the name answers; „give me its id” stays a desktop and detail-page action. So the tablet form is the shared cell’s first line, relocated — not a third variant of it.
