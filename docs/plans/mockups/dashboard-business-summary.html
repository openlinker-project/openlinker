What this mockup decides

The one encoding

Every category collapses to the same three buckets, so a glance means the same thing in Listings as it does in Invoices. Exact platform statuses live one level deeper, on the connection row. The attention segment never disappears: any non-zero count keeps a 4 px minimum width, so 2 failures out of 1,284 are still visible.

Windows

  • Listings is a stock metric. The hero number is what is live right now and ignores the range. The range drives the delta line underneath (+34 new · 12 ended).
  • Shipments, invoices and payments are flow metrics. Their totals are scoped to the selected 7 / 30 / 90 day window.

Connection axis

  • A connection appears in a category only if it has the capability. Allegro never shows up under Invoices; inFakt never shows up under Listings. Resolved from capabilities, never from platformType.
  • A capable connection with nothing in range shows an explicit 0 row, not a hidden one — a channel that quietly stopped producing shipments is exactly what you want to notice.
  • Hidden connections are named in a footnote per category so the numbers are never silently partial.
  • Shipments are grouped by the connection that sourced the order, matching the connectionId filter already on GET /shipments. If per-carrier is the more useful cut, that is a one-line change of the group key.

Backend this needs

  • Shipments and invoices are derivable today — both list endpoints return total and accept connectionId plus status. Still worth one aggregate endpoint rather than N×M probe calls.
  • Listings needs a new read. The listings list has no status filter and OfferMapping.status is an untyped string; live publication status is only readable per product via GET /listings/products/:productId/offer-status.
  • Proposed: GET /dashboard/business-summary?range=30d returning one bucketed block per category per connection, following the shape GET /orders/status-summary already established. Buckets are computed server-side so the FE never re-implements the mapping table above.
  • Four independent reads means four independent failures, so each card degrades on its own. A failed read shows an error card, never a 0 — “no invoices” and “we could not ask about invoices” must never look alike.

Payments

The domain does not exist yet. The card is present but dashed and dimmed, and its accordion section does not open. Reserving the slot now means shipping payments later is a data change, not a re-layout.
