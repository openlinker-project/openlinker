# Implementation plan: the pre-commit hook proves which worktree it validates (#2767)

## 1. Goal and layer

A pre-commit hook is a statement about the commit it gates. #2767 reports a hook whose
lint / `check:invariants` output named a SIBLING worktree's paths, so a green or red hook
described a tree that was not being committed. Layer: DX (hook + invariant script); no
backend, frontend runtime or migration.

**Non-goals**: making a hook appear in a worktree that never ran `pnpm install` (see Finding 3);
changing what lint / type-check / smart-test do once the tree is proven.

## 2. Findings (measured on `origin/main` eb11df527, fresh worktree, before `pnpm install`)

1. `core.hooksPath` is `.husky/_` - a RELATIVE path in the shared `.git/config`. Git resolves it
   against the worktree the hook runs in, so each worktree uses its OWN `.husky/_`. The "shared
   hooks path" hypothesis in the issue does not hold.
2. `scripts/smart-test.mjs` derives its root from `import.meta.url`, i.e. from its own file.
   Not the culprit either.
3. A worktree that never ran `pnpm install` has NO `.husky/_` (generated by the `prepare`
   script, untracked) and no `node_modules`. Git then finds no hook and the commit proceeds with
   no checks at all - a related, different hole; documented, not fixable from inside a hook.
4. With no own `node_modules`, plain `node` resolves upward: `require.resolve('eslint')` landed in
   the MAIN checkout's `node_modules` (`/home/.../openlinker/node_modules/...`). For a worktree
   nested under another worktree (this repo has several) it would land in the parent worktree.
   `pnpm` itself only prepends the tree's own `node_modules/.bin`, so a missing install fails
   loudly there.
5. The remaining and most plausible mechanism: `node_modules` linked into a sibling worktree to
   skip an install. The workspace links (`node_modules/@openlinker/*`) then resolve to the
   sibling's packages, so eslint / tsc report that tree's paths while "checking" this one. A plain
   `cp -r` does not do this: pnpm writes workspace links as relative symlinks, so a copy resolves
   into the copy's own tree.

Root cause stated as far as it can be: the hook never asserted that the tree it runs in is the
tree whose code the tools resolve. The exact trigger in the reporter's run is not recoverable
and is NOT claimed.

## 3. Design

`scripts/check-worktree-identity.mjs`, run as the FIRST step of `.husky/pre-commit` and also in
`check:invariants`:

- facts: `git rev-parse --show-toplevel`, `process.cwd()`, `realpath` of `node_modules`, of every
  `node_modules/@openlinker/*` link, and of the `node_modules` directory of every package named by
  the `packages:` globs in `pnpm-workspace.yaml` (`apps/*`, `libs/*`, `libs/integrations/*`).
- rules (pure `evaluateWorktreeIdentity`): cwd real path == toplevel real path; every observed
  real path is inside the toplevel; `node_modules` must exist (a missing install is reported,
  not skipped - Finding 4); the set of observed workspace links must be non-empty, so a scan
  that found nothing cannot pass (the repo's "matched nothing" rule).
- fail loudly: exit 1 with each offending path and a one-line remedy. No bypass flag beyond the
  existing `--no-verify`.
- self-check: pure cases plus a real-filesystem case in a temp dir (own `node_modules` passes;
  `node_modules` symlinked to a sibling fails; a workspace link into a sibling fails; no
  `node_modules` fails; zero links fails).

## 4. Steps and acceptance

| # | File | Change | Acceptance |
|---|---|---|---|
| 1 | `scripts/check-worktree-identity.mjs` | new script + `--self-check` | self-check green, each rule has a case that fails when it is removed |
| 2 | `.husky/pre-commit` | run it before lint | hook refuses on a sibling-linked tree, passes on a healthy one |
| 3 | `package.json` | add to `check:invariants` (self-check + run) | `pnpm check:invariants` green |
| 4 | `docs/engineering-standards.md` (git workflow) or `docs/lessons.md` | one paragraph: worktree needs its own `pnpm install`; what the guard proves | present |

## 5. Validation

- Real red/green: in a scratch worktree, symlink `node_modules` to a sibling and run the script
  (red), then restore (green).
- Risk: a contributor who deliberately shares `node_modules` between two worktrees now gets a
  refusal. That is the case the issue asks to fail on; the remedy line says to run
  `pnpm install` in the worktree.
- Another open PR appending to the `check:invariants` line conflicts on `package.json`: keep
  every entry and both halves of each `--self-check &&` pair.
- `/pre-implement` gate skipped: one new self-contained script and a hook line, no port, token,
  barrel, DTO or schema surface to collide with.
