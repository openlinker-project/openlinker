## 1. What this measures

- **arm A** - the two-pass ingestion shape (#2330). Pass 1 discovers returns via
  the cursor-paged feed and fans out; pass 2 re-reads OL's own non-terminal
  returns, because a return feed can only report that a return EXISTS and
  Allegro's `CustomerReturn` carries no `updatedAt`.
- **arm B** - custody disposition with a restock that must BLOCK, and one that
  must succeed. The blocked one is the point.
- **arm C** - the orphan reconcile (#2332): a return naming an order OL has
  since ingested gets attributed; one naming an order OL has never seen stays
  orphaned.

## 3. Both directions, in all three arms

This scenario is unusual in the campaign for asserting the refusal as hard as
the success, and each refusal is a different kind:

- **arm B** disposes a line whose sku resolves to no product variant. The
  expected result is a NAMED block - `unresolved-product`, carrying the sku, the
  connection id and the connection name - never a silent no-op and never a
  counter that moves. A restock that quietly does nothing is stock in the wrong
  place with every counter internally consistent.
- **arm C** asserts `permanentOrphansAfter=10`. A reconcile that attributed
  those would be worse than one that attributed nothing: `claimAttribution` is
  monotonic and there is no unmatch, so a wrong guess is uncorrectable in the
  product.

## 4. Reading 5 199/h

Ingestion here is dominated by the per-return hydrate call, not by OL's own
write. The figure is a statement about this stand's Allegro stub at its
configured latency; a real marketplace publishes its own rate limit, which will
be the binding constraint long before this number is.

Pass 2's 2 416 ms is the more interesting half operationally: it is the cost of
the ONLY change-detection channel returns have, and it is paced by its own cron
rather than by this measurement.
